# プリント依頼・質問ヘルプ アプリ ― 構成案と画面イメージ

作成日: 2026-09-25

このファイルは「何を・どういう仕組みで作るか」をまとめたものです。
実装はこの構成で進めています。あとから変えたい点があれば、この文書を基準に相談してください。

---

## 1. 全体の構成（結論）

**採用: 静的サイト（Netlify）＋ Supabase（無料のデータベース）**

```
 生徒のスマホ / 共有タブレット / 学校タブレット           講師の iPhone / PC
 ┌────────────────────────────┐          ┌──────────────────────┐
 │ https://○○○.netlify.app/    │          │ https://○○○.netlify.app/teacher.html │
 │  生徒画面（ログイン不要）    │          │  講師画面（合言葉で入る）            │
 └──────────────┬─────────────┘          └──────────────┬───────────┘
                │ 依頼を送る / 自分の状態を見る          │ 一覧・対応・メモ・履歴・CSV
                ▼                                        ▼
        ┌──────────────────────────────────────────────────────┐
        │  Supabase（無料プラン）                               │
        │   ・requests  … 依頼の記録（削除せず全部残す）         │
        │   ・students  … 生徒名簿（講師画面から貼り付けで取込） │
        │   ・app_settings … 合言葉                             │
        │   ・SQL関数 … 依頼作成 / 状態変更 / 集計（全部ここで検査）│
        └──────────────────────────────────────────────────────┘
```

- 生徒画面・講師画面はただの HTML ファイル（ビルド不要）。Netlify に**ドラッグ＆ドロップ**するだけで公開できます。
- データは Supabase に保存。全端末で同じデータを共有し、**5秒ごとの自動更新**で講師画面に反映します。
- どちらも無料枠で運用できます（想定規模：1教室 数十人／日 なら余裕）。

### 1-1. 候補の比較

| 候補 | 学校フィルタで開けるか | 生徒ログイン | 更新の速さ | 管理のしやすさ | 評価 |
|---|---|---|---|---|---|
| **A. Netlify ＋ Supabase（採用）** | ◎ URL は `○○.netlify.app`。script.google.com を一切使わない | 不要 | 5秒ごと（設定で変更可） | ○ 名簿は講師画面で貼り付け取込。データは Supabase の画面で表として見られる | **推奨** |
| B. Google スプレッドシート ＋ GAS | △ 公開URLが `script.google.com/...` になり、学校フィルタで**ブロックされやすい**。さらに画面は `googleusercontent.com` の中で開く二重構造で、ホーム画面追加もうまく動かないことが多い | 「全員」公開なら不要 | 遅い（1回の通信に1〜3秒） | ◎ シートをそのまま見られる | 学校端末が主役なら不利 |
| C. Firebase（Firestore ＋ Hosting） | ○ `○○.web.app` | 不要 | ◎ リアルタイム | △ 公開に Node.js のコマンド操作が必要。無料枠が「読み取り回数」制なので、講師画面の自動更新で枠を使い切るおそれ | 次点 |

**A を採用する理由**
1. 学校のフィルタは「Google Apps Script（script.google.com）」を止めていることが多く、B は一番のリスクを抱えたままになる。
2. A は公開手順が「フォルダをブラウザに落とす」だけで、コマンド操作が不要。
3. 通信先が 2 つ（netlify.app / supabase.co）だけなので、ブロックされた時に原因が特定しやすい。

### 1-2. フィルタリングのリスクと代替案

| 起こりうること | 対策 |
|---|---|
| `○○.netlify.app` が開けない | 画面のファイルは「ただの HTML」なので、**GitHub Pages（`○○.github.io`）や Cloudflare Pages（`○○.pages.dev`）に 10 分で置き換え可能**。手順書に載せます |
| `○○.supabase.co` への通信が止められる | 無料の Supabase を別リージョンで作り直す／Cloudflare の無料プロキシを挟む、の順で対応。まず学校端末 1 台で**当日朝に動作確認**するのが確実です |
| 短縮URL（bit.ly 等）が開けない | 短縮URLサービスは学校フィルタで止まりがちなので**使いません**。Netlify のサイト名を短く決めて（例 `juku-help.netlify.app`）そのまま掲示します |
| CDN（ライブラリ配信サイト）がブロック | Supabase 用ライブラリは**サイト内に同梱**して、外部 CDN に依存しません |

### 1-3. 費用と上限（Supabase 無料プラン）

- データ容量 500MB（依頼 1 件 ≒ 1KB → 数十万件でも余裕）
- 通信量 5GB/月（講師 3 人が 5 秒ごとに 4 時間/日 更新しても月 1GB 未満の見込み）
- **1 週間まったく使わないとプロジェクトが「一時停止」**になります。長期休み明けは Supabase の管理画面で「Restore」を押すだけで復帰します（手順書に記載）。

## 2. 画面イメージ

### 2-1. 生徒画面（`index.html`）

初回のみ：

```
┌─────────────────────────────┐
│  この端末は？                │
│  ┌─────────────────────┐    │
│  │ 📱 自分の端末         │    │ → 本人・教室・席を記憶して次回自動入力
│  └─────────────────────┘    │
│  ┌─────────────────────┐    │
│  │ 🏫 みんなで使う端末   │    │ → 送信後に入力を自動リセット
│  └─────────────────────┘    │
│  （あとで画面右上の⚙で変更できます）│
└─────────────────────────────┘
```

トップ：

```
┌─────────────────────────────┐
│ 質問・プリント          ⚙   │
│                             │
│  ┌───────────────────────┐  │
│  │ 📄 プリントがほしい     │  │  ← 大きなボタン
│  └───────────────────────┘  │
│  ┌───────────────────────┐  │
│  │ ✋ 質問したい           │  │
│  └───────────────────────┘  │
│                             │
│  あなたの依頼              │
│  ┌───────────────────────┐  │
│  │ #12 数学 質問  ⏳待ち   │  │ ← 自分の分だけ。取り消しボタンつき
│  │  あと2人 / 送信 3分前   │  │
│  └───────────────────────┘  │
│  [受付番号で確認する]        │  ← 共有端末のとき
└─────────────────────────────┘
```

入力（プリントの例。質問も同じ流れ）：

```
 1. だれ？    学年 [中1][中2][中3]  → 名前ボタン一覧（or 生徒番号入力）／その他（手入力）
 2. どこ？    教室 [A教室][B教室][自習室]   席 [ 12 ]
 3. 教科      [英][数][国][理][社][他]
 4. 内容      （一次関数の復習プリント）      枚数（任意）
    質問なら  「すぐ来てほしい」／「あとででOK」
 5. [ 送信する ]
```

送信後：

```
┌─────────────────────────────┐
│   ✅ 受け付けました！        │
│                             │
│      受付番号  12           │  ← 大きく表示（共有端末では控えてもらう）
│      いま 3 番目 です        │
│                             │
│  [ 状態を見る ]  [ 閉じる ]  │
└─────────────────────────────┘
```

- 他の生徒の依頼・講師メモは表示しません。
- 「自分の端末」モード：この端末から送った当日の依頼を自動表示。
- 「みんなで使う端末」モード：送信後に選択をリセット。状態確認は受付番号を入力。

### 2-2. 講師画面（`teacher.html`）

```
┌─────────────────────────────────────┐
│ 合言葉 [ ______ ]  講師名 [ 山田 ]  [入る]│  ← 初回のみ。iPhoneに記憶
└─────────────────────────────────────┘

┌─────────────────────────────────────┐
│ 待ち 5 │ 🔴すぐ 2 │ 最長 12分 │ 🔔 ⚙ │  ← サマリー
│ [待ち(5)] [対応中(2)] [完了(8)] [記録] │  ← タブ
│ 教室 [全部▼]  種類 [全部▼]           │  ← 絞り込み
├─────────────────────────────────────┤
│ A教室 12席  佐藤 花子(中2)     12分  │  ← 1行目
│ 🔴質問 数学  テキストp.32 問3         │  ← 2行目（すぐ来てほしいは赤）
│   [対応する]                          │
├─────────────────────────────────────┤
│ B教室 3席   鈴木 太郎(中3)      8分  │
│ 📄プリント 英語  関係代名詞 ×2枚      │
│   [対応する]                          │
└─────────────────────────────────────┘
```

- 「対応する」を押すと担当講師名つきで「対応中」へ。
- 「完了にする」を押すとメモ入力：定型ボタン（理解できた／要フォロー／類題を渡した…）＋自由記入。
- 新しい依頼が来ると音＋タブの件数バッジ＋画面上部が光る（iPhone Safari で動く範囲）。
- 日付が変わると完了分は一覧から消え、「記録」タブで見られる。
- 「その他（手入力）」で来た依頼は、カードから名簿の生徒に紐づけ直せる。

### 2-3. 記録ページ（講師画面の「記録」タブ）

```
 生徒 [中2 佐藤 花子 ▼]   期間 [2026-09-01] 〜 [2026-09-30]  [表示]

 集計：質問 8回（数学5・英語2・理科1） / プリント 3回 / 要フォロー 2件

 [📋 保護者報告のもとを作る]  → 文章が出る → [コピー]
 [⬇ CSV書き出し（全生徒・期間内）]

 一覧：
  9/03 18:12 質問 数学 「一次関数の変域」 担当:山田  メモ:要フォロー／類題を渡した
  9/05 19:40 プリント 英語 「不定詞の復習」 ×2 担当:田中 メモ:理解できた
  ...
```

報告文は**講師メモと集計だけを材料に**、ルールで組み立てます（AI ではないので事実にないことは書きません）。例：

> 9月1日〜9月30日の記録です。質問は8回（数学5回・英語2回・理科1回）、プリント依頼は3回でした。
> 講師メモ：9/3 数学「一次関数の変域」：要フォロー、類題を渡した。9/5 英語「不定詞の復習」：理解できた。
> 「要フォロー」となった項目が2件あります。

### 2-4. 設定ページ（講師画面の ⚙）

- 名簿の取り込み：スプレッドシートの「生徒番号・氏名・学年・学校名」列をコピーして貼り付け → 取込。
- 合言葉の変更。
- 端末の通知音 ON/OFF。

### 2-5. QR・掲示用ページ（`qr.html`）

サイトを開いたURLの QR コードと短いURLを大きく表示。印刷して教室に貼る用。

## 3. データの持ち方

**requests（依頼）** ― 1 件 1 行。消さない。

| 列 | 内容 |
|---|---|
| id / day / receipt_no | 通し番号 / 日付 / その日の受付番号 |
| student_id / student_name / grade | 名簿の生徒（その他の場合は空）/ 表示名 / 学年 |
| classroom / seat | 教室 / 席 |
| kind / subject / content / copies / urgency | print or question / 教科 / 内容 / 枚数 / now or later |
| status | waiting → in_progress → done（または cancelled） |
| teacher / started_at / done_at / memo / memo_tags | 担当講師 / 対応開始 / 完了 / メモ自由記入 / 定型タグ |
| created_at / device_id | 依頼時刻 / 端末の識別子（いたずら対策用。個人情報ではない） |

**students（名簿）**: student_no, name, grade, school, active
**app_settings**: 合言葉（生徒側からは読めない）

## 4. セキュリティと安全策

- 生徒側はログインなし。ただし**データベースの表には直接触れず**、決められた操作（依頼を送る／自分の依頼を見る／取り消す）だけができる「関数」経由にします。生徒が他人の依頼を覗く経路はありません。
- 講師の操作は全部「合言葉つき関数」で、サーバー側で合言葉を確認します（画面のソースを見ても合言葉は分かりません）。
- いたずら対策：同じ端末から **15 秒以内の連続送信を拒否**、**1 時間に 30 件まで**、文字数上限あり。
- 個人情報は 名前・学年・学校名・席 のみ。名簿の「学校名」は生徒画面には送りません。

---

## 5. 設定を 1 か所に

`config.js` に以下をまとめます（テキストエディタで書き換え → 再アップロードで反映）。

- 教室名の一覧、教科の一覧、学年の一覧
- 完了メモの定型文
- 自動更新の間隔（秒）
- Supabase の URL と公開キー

合言葉だけはデータベース側（講師画面の設定から変更）。

## 6. 段階的な進め方

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | 依頼送信・講師一覧・対応中/完了・完了メモ・履歴保存・端末モード・受付番号・取り消し | 今回実装 |
| 2 | 記録ページ（生徒別一覧・集計）・報告文生成・CSV・名簿貼り付け取込・紐づけ | 今回実装 |
| 3 | 公開手順・QR ページ・ホーム画面追加 | 今回実装 |
| 4（後日） | プッシュ通知、リアルタイム更新（WebSocket）、Google スプレッドシートからの名簿自動同期 | 必要なら |

**動作確認用の「お試しモード」**も入れてあります。Supabase を設定する前でも、同じブラウザ内で生徒画面→講師画面の流れを試せます（データはそのブラウザにだけ保存）。
